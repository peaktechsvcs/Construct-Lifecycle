============================================================
WORKSPACE NAVIGATION — CUSTOMER BEFORE PROJECTS
============================================================

Update the Construct Lifecycle workspace navigation order.

The Workspace section should be:

WORKSPACE
- Overview
- Customers
- Projects
- Follow-ups

Customers must appear ABOVE Projects.

Do not redesign the sidebar.

Maintain the existing Construct Lifecycle look and feel.

============================================================
CUSTOMER → PROJECT RELATIONSHIP
============================================================

Customers are first-class business records.

A Project should normally be associated with a Business Customer/Client.

Hierarchy:

Software Customer / Tenant
    ↓
Environment
    ↓
Business Customer
    ↓
Project

Example:

Northline Supply
    ↓
Production
    ↓
ABC Homebuilders
    ↓
Cedar Ridge Development

============================================================
NEW PROJECT — CUSTOMER FIELD
============================================================

When a user creates a new Project, include a Customer field.

Example:

Customer
[ Select or enter customer... ]

This field must support BOTH:

1. Selecting an existing Customer.
2. Entering a new Customer.

The user should not have to leave the New Project workflow to create a Customer.

============================================================
SELECT EXISTING CUSTOMER
============================================================

When the user opens the Customer field:

Show existing active Business Customers belonging to:

- the active tenant/customer
- the active environment

Example:

Customer
[ ABC Homebuilders            ]
  Summit Development
  Red Rock Construction
  Canyon Builders

Support:

- Search
- Keyboard selection
- Mouse selection

Do not show:

- another tenant's customers
- another environment's customers
- archived customers by default
- Construct Lifecycle SaaS tenants

============================================================
ENTER NEW CUSTOMER FROM PROJECT
============================================================

If the user types a Customer name that does not already exist, allow that entry to create a new Business Customer record.

Example:

User types:

Front Range Builders

No matching Customer exists.

Present an action such as:

+ Create "Front Range Builders"

When selected:

1. Create a new Business Customer record.
2. Save it to the active tenant.
3. Save it to the active environment.
4. Automatically associate it with the Project being created.
5. Keep the user in the New Project workflow.

Do not require navigation to the Customers page first.

============================================================
DUPLICATE CUSTOMER CHECK
============================================================

Before creating a new Customer from the Project form, perform a duplicate check within the active tenant/environment.

Check reasonable matching criteria such as:

- Company Name
- Display Name
- Normalized Company Name

Example:

Existing:
ABC Homebuilders

User enters:
ABC Home Builders

If a likely match exists:

Show:

Possible existing customer

ABC Homebuilders

[ Use Existing Customer ]

and:

[ Create New Anyway ]

Do not silently create obvious duplicates.

Do not block legitimate similarly named organizations without allowing an authorized user to proceed.

============================================================
PROJECT SAVE BEHAVIOR
============================================================

When the Project is saved:

Store the stable Business Customer identifier.

Example:

project.business_customer_id

Do not store only:

"ABC Homebuilders"

as free text.

The displayed Customer name should come from the related Customer record.

============================================================
TRANSACTIONAL CREATION
============================================================

When a new Customer is created as part of New Project:

Ensure the workflow avoids partial or orphaned records where practical.

Preferred sequence:

1. Validate Project form.
2. Validate Customer entry.
3. Check for existing Customer.
4. Create Customer if required.
5. Associate Customer ID to Project.
6. Create Project.
7. Commit successfully.

If Project creation fails after Customer creation, handle the failure cleanly according to the application's transaction architecture.

Do not accidentally create large numbers of orphaned Customers from failed Project submissions.

============================================================
CUSTOMER REQUIRED
============================================================

Customer should normally be required for a Project.

Example:

Customer *
[ Select or enter customer... ]

If there are legitimate future workflows for projects without a Customer, support those explicitly rather than allowing accidental empty Customer relationships.

For the current implementation:

Require Customer unless existing project logic explicitly requires otherwise.

============================================================
EDIT PROJECT CUSTOMER
============================================================

Authorized users may change the Customer associated with a Project where business rules permit.

If changing a Project Customer:

- Select from existing Customers
- Allow new Customer creation if permitted
- Update stable Customer ID
- Audit the relationship change
- Do not modify historical financial documents automatically unless business rules explicitly support it

Consider warning when changing Customer on a Project that already contains contracts, invoices, payments, or other significant transactions.

============================================================
ARCHIVED CUSTOMERS
============================================================

Archived Customers:

- remain associated with historical Projects
- remain visible when viewing those Projects
- do not appear in the normal New Project Customer selector

If an archived Customer needs to be used again:

Require restoration/reactivation first, or provide an explicit restore flow.

============================================================
FINAL RULE
============================================================

Workspace navigation must be:

Overview
Customers
Projects
Follow-ups

Customers come before Projects because the Customer is the parent business relationship under which Projects are created.

When creating a Project:

The user may either:

SELECT AN EXISTING CUSTOMER

or

ENTER A NEW CUSTOMER

If the entered Customer does not exist and the user has permission:

CREATE THE CUSTOMER RECORD
+
SELECT IT AUTOMATICALLY
+
CONTINUE CREATING THE PROJECT

Do not store newly typed Customer names as unstructured Project text.

A new Customer entered from a Project must become a real Construct Lifecycle Business Customer record.
