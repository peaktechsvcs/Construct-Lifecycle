============================================================
SUBSCRIPTION-BASED MEMBERSHIP
============================================================

Add subscription-based membership for Construct Lifecycle software customers.

Support both:

- Monthly subscriptions
- Annual subscriptions

The subscription belongs to the Construct Lifecycle software customer / tenant.

Do NOT confuse:

Construct Lifecycle Subscription Customer
with
Business Customer / Client

Hierarchy:

CONSTRUCT LIFECYCLE
        ↓
SOFTWARE CUSTOMER / TENANT
        ↓
SUBSCRIPTION
        ↓
USERS / FEATURES / ENVIRONMENTS
        ↓
BUSINESS CUSTOMERS
        ↓
PROJECTS

Example:

Construct Lifecycle
    ↓
Northline Supply
    ↓
Construct Lifecycle Professional — Annual
    ↓
Users / Integrations / Features
    ↓
ABC Homebuilders
    ↓
Cedar Ridge Development

SUBSCRIPTION BILLING FREQUENCY
============================================================

Support:

MONTHLY

Customer pays once per month.

ANNUAL

Customer pays once per year.

Each plan may define separate pricing for:

monthly_price
annual_price

Annual pricing may include a discount compared with paying monthly.

Do not calculate annual pricing as monthly_price × 12 unless that is explicitly how the plan is configured.

Store annual and monthly pricing independently.

============================================================
PAYMENT INFORMATION SECURITY
============================================================

Do NOT store raw credit-card information in Construct Lifecycle.

Do not store:

- Full card number
- CVV
- Raw payment credentials

Use payment-provider hosted/tokenized payment methods.

Construct Lifecycle may display safe metadata such as:

Visa ending in 4242
Expires 09/29

when supplied securely by the billing provider.

============================================================
SUSPENDED SUBSCRIPTION
============================================================

If a subscription is suspended for billing reasons:

Preserve:

- Tenant
- Users
- Projects
- Customers
- Documents
- Integration mappings
- Configuration
- Audit history

Do not delete operational data.

Access behavior should follow platform policy.

A reasonable future policy is:

- Customer administrators can access billing.
- Business application access is restricted.
- CLC Admin can access tenant for support.

Do not implement destructive deletion as part of suspension.

============================================================
SUBSCRIPTION ACCEPTANCE CRITERIA
============================================================

[ ] Monthly subscriptions are supported.

[ ] Annual subscriptions are supported.

[ ] Monthly and annual prices are independently configurable.

[ ] Subscription plans are configurable.

[ ] Subscription belongs to the Construct Lifecycle software customer/tenant.

[ ] Business Customers are not treated as subscription accounts.

[ ] Customer admins can view authorized subscription/billing information.

[ ] CLC Admin can manage authorized subscription information.

[ ] Subscription status is centrally tracked.

[ ] Automatic renewal architecture is supported.

[ ] Trial architecture is supported.

[ ] Billing provider architecture is provider-agnostic.

[ ] Raw credit-card information is not stored by Construct Lifecycle.

[ ] Failed payments do not delete customer data.

[ ] Cancellation at period end is supported.

[ ] Reactivation is supported where allowed.

[ ] Monthly-to-annual changes are supported.

[ ] Annual-to-monthly changes are supported.

[ ] Plan upgrades/downgrades are supported.

[ ] Feature entitlement resolution is centralized.

[ ] Plan names are not hard-coded throughout the UI.

[ ] CLC Admin entitlement overrides are supported.

[ ] Customer user permissions remain required.

[ ] Customer Branding remains hidden unless CLC Admin enables it.

[ ] Integration availability respects plan + CLC entitlement + user permission.

[ ] Public API availability respects subscription entitlements.

[ ] D/T/D availability can be subscription controlled.

[ ] Subscription changes are audited.

[ ] Billing webhooks are securely processed.

[ ] Billing UI preserves the existing Construct Lifecycle look and feel.

============================================================
FINAL SUBSCRIPTION PRINCIPLE
============================================================

Construct Lifecycle is a subscription-based SaaS platform.

The subscription model must support:

MONTHLY
or
ANNUAL

The subscription controls commercial eligibility for platform capabilities.

Actual feature access is determined by:

SUBSCRIPTION PLAN
        +
CLC ADMIN ENTITLEMENTS
        +
ENVIRONMENT RULES
        +
CUSTOMER USER PERMISSIONS

Do not hard-code feature access to plan names.

Build a centralized subscription + entitlement architecture so future pricing, plans, integrations, API access, Customer Branding, D/T/D, user limits, and premium capabilities can be changed without redesigning the application.
